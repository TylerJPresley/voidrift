# Skill: Technical Writing

## Core Philosophy
- **Documentation as Code:** Treat documentation with the same rigor as code; keep it in the repository and version-controlled.
- **Clarity & Brevity:** Use simple, direct language. Avoid jargon unless defined.
- **Audience-Centric:** Write for the specific reader (Developer, Operator, End User).

## Implementation Rules
- **README Standards:** Every project and module must have a clear README covering Purpose, Setup, Usage, and Testing.
- **API Documentation:** Maintain up-to-date OpenAPI, GraphQL, or Javadoc/TSDoc definitions.
- **Architecture Decision Records (ADR):** Document the "Why" behind significant technical choices.
- **Commit Messages:** Write clear, concise messages following the Conventional Commits standard.

## Structure
- **Guides & Tutorials:** Provide step-by-step onboarding for common tasks.
- **Changelog:** Maintain a clear, human-readable log of all notable changes (Keep a Changelog format).
- **Formatting:** Use consistent Markdown, including proper headers, code blocks, and lists.
